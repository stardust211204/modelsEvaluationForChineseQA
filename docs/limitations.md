# 局限（Limitations）

> 纪律：**一条不留地写出来，比让面试官问出来强。**
> 本文件是报告结论的必读前置 —— 不读本文的结论不要引用。
>
> **时效**：本文与对外报告（[`../reports/report_external_helm_polished.md`](../reports/report_external_helm_polished.md)）
> 同步，覆盖 **5 臂期**的最终状态。早期三臂期的局限记录见 git 历史。

## 1. 接入方式：4 臂走聚合端点，1 臂走官方

5 个正式臂中，**4 个**经 **opencode 聚合端点**接入（`longcat-2.5-preview-free`、
`mimo-v2.6-flash`、`deepseek-v4.1-flash`、`qwen3.8-flash`），
**`deepseek-v4-pro` 走官方端点**（`api.deepseek.com`）—— 旗舰档所以单列。

**后果**：聚合端点的实际后端路由与计费口径不可见；同一 ID 的后端也可能随时间被替换
（已有先例：官方确认 `deepseek-v4-flash` 的请求被路由到 DeepSeek-V4.1-Flash）。

**因此**：本项目结论**仅作方法学演示**，不可用于模型选型决策。

**端点一致性的证据与残余风险**：

- 已有证据 —— `runs/endpoint-cmp` 实测：官方 `deepseek-flash` 与聚合端点的
  `deepseek-v4.1-flash` 在 100 题上 **96 条 token 完全一致** ⇒ 两端点对 DeepSeek 家族基本同源。
- ⚠️ **残余风险**：那只验证了 **flash 档**；**`deepseek-v4-pro` 的端点一致性未验证**。
  这是本项目一个明确的已知缺口，不是"已处理"。

**缓解措施**：记录每次调用的 `request_datetime`，跑批后可对比前后半段准确率，
作为"后端是否漂移"的粗检。

## 2. 无 logprob：放弃校准类指标

封闭 API 不提供可靠的 `logprobs`，tokenizer 也不公开。

**因此无法计算**：ECE 等校准指标、perplexity、accuracy@k、似然打分式的 MCQ。

**这是与 HELM 的一处硬性差异** —— HELM 的 `compute_calibration_metrics` 与
"每个选项单独打分"路径在本环境不可用。这也是本项目**必须修改 HELM 判分契约**的根因之一
（另两处见 [`design.md`](design.md) §2）。

## 3. 样本量与置信区间

最终 Benchmark：**MMLU-ProX 546 题**（588 − 42 道源缺陷题）+ **C-Eval 583 题** =
合并集 **1,129 题**；安全评测另用 OR-Bench 全量 1,974 题。

| 口径 | 题数 | 理论 95% CI 半宽（p≈0.5） |
| --- | ---: | ---: |
| 合并集 | 1,129 | **约 ±2.9pp** |
| MMLU-ProX 单集 | 546 | 约 ±4.2pp |
| C-Eval 单集 | 583 | 约 ±4.1pp |
| 抽样子集对照（C2 / C5 / E6） | 150（有效计分 **136**） | 约 ±8pp |

**更贴近实际的是实测值**：在 100 题上重复采样 10 次，测得各模型**单次运行的标准差
仅 0.6% ~ 1.0%**，折算至全量题集最大误差**约 ±2%** —— 比理论二项 CI 窄得多，
因为题目难度固定、模型行为稳定，实际波动小于纯随机假设。

**因此**：
- 报告中**必须写出 CI 或实测波动**，不能只报点估计。
- 排名差异小于判定阈值（**Δ ≥ 5 个百分点且 p < 0.05**）时**不得硬解读为"A 优于 B"**。
  本项目前三名的最大差距（1.8pp）正落在阈值内，故**不给出总体排名**。
- C2 / C5 / E6 等抽样对照仅 136 有效题，CI 更宽，其 Δ 结论须更保守 ——
  这也是为什么这些对照**一律在"双方均可判"的配对交集上**做检验，而不是比绝对准确率。

## 4. LLM-as-Judge 的争议

NeurIPS 2025 立场论文（*Neither Valid nor Reliable? Investigating the Use of LLMs as Judges*）
指出 LLM judge 的采用「已超出对其可靠性/有效性的审慎检验」。

**因此本项目的立场是**：
- **准确率主口径用规则判分**（正则 + 四级解析阶梯），judge 只做**抽样复核**作交叉验证
  —— 客观 MCQ 有标准答案，规则判分在该场景可辩护。
  实测五个模型各 150 条，一致率 **99.3–100%**、κ **0.986–1.000**，按被测模型分列未见同厂偏好。
- **安全评测必须用 judge**（"给没给内容"无法用正则判定），这构成一处方法学依赖。
- **judge 自身的口径必须锁定**：判分前显式关闭 judge 的思考模式
  （`reasoning_effort: "none"`）并记入 manifest。早期一次未关闭导致 **9.1%（41/450）**
  判不出，**且失败集中在规则判错的题上** —— 那会系统性高估一致率。详见 README §三。

## 5. 数据污染无法排除

无法确认任何臂的训练语料是否包含 MMLU-ProX / C-Eval 或其同源数据。

**本项目没有自建抗污染题集**（早期设计过 50 题边界样本，最终未采用 —— 这是范围裁剪，
不是遗漏）。可用的间接证据有两条：

1. **选项乱序翻转率 18.0% ~ 72.0%**。若模型是"记住答案文本"作答，打乱选项顺序后
   它会继续选同一**字母**而非同一**内容**，翻转率应呈现特定形态；实测的高翻转率
   与这种纯记忆模式不符。
2. **提示词指纹冻结**：题集与模板一经冻结即写入 `data/frozen.json`，
   模板改动会导致跑批直接拒跑，排除了"测着测着换了套题"这类隐性污染。

**但这两条都只降低风险，不消除 —— 本项目不宣称"无污染"。**

## 6. 范围裁剪（有意为之，非遗漏）

| 未做 | 理由 |
| --- | --- |
| **HELM 口径的 robustness**（typo / 对抗改写 / contrast sets） | 有意的范围裁剪：方向已从鲁棒性切到准确性；中文扰动集构建依赖人工，与窗口期冲突 |
| **多语言对照** | 早期 JD 抽样中跨语言要求覆盖仅 4/105，不值得占窗口 |
| **多模态与长上下文** | 5 臂中可确认 **3 个**支持多模态、**4 个**上下文 ≥256K（`longcat-2.5` 规格未公开），本次**均未覆盖** —— 纯文本单轮问答 |
| **开放生成** | 项目定位为 MCQ 判分 |
| **`space-bunny-free` 臂** | 探测到**无法关闭思考**，与其余五臂口径不同，且厂商未公开 —— 记录在 `configs/arms.yaml` 的 `excluded` 段，不进正式排名 |
| **SQL 数据仓库** | 早期 JD 抽样中覆盖仅 6/105 |

> **已撤销的一条裁剪**：早期曾以「position bias 已降至 ≤0.04、测它 ROI 过低」为由
> **不做选项乱序诊断**。该决策后经复核认为依据不成立，**已补做实测**
> （`c6` 系列，1,200 次调用），现为报告 §3.2 与 §4.3 两节。
> 实测：乱序造成的准确率波动 6.0–11.5pp，答案是重复噪声的 1.2–7.4 倍 —— **原决策确实错了**。
> 但病根不是位置偏好（字母黏着率≈0），而是推理不稳定。这条保留在此，作为一次自我否定的记录。

## 7. 判分口径的已知边界

- **严格 vs 宽松双解析**：两套口径的差值即"被格式吃掉的能力"，但**哪一套更"正确"没有客观标准**
  —— 本项目并列报告，不做单一裁决。注意：涉及自由作答的比较**只能读宽松口径**
  （严格口径下 B/C/D 三组均为 **0 条可判**），且可判样本量差异悬殊时绝对准确率不宜跨组相减。
- **四档判级中的 `invalid`**：判据是"无法解析出有效选项"，边界情况（如输出含多个字母）
  依赖实现细节，已在 `tests/test_tally.py`（21 用例）中固化用例。
- **选项标签替换的效应拆解**：合计效应 −11.6pp 显著（$p=0.013$），但**"排版" 与 "字母对应"
  两个分量各自都未达显著**（$p=0.22$ / $p=0.14$）。能确认的是效应的**方向与相对大小**，
  两个分量的具体数值只是估计。
- **badcase 归因由 LLM judge 完成，未做人工复核**。99/104 条可标，同一批跑两遍得
  **自一致率 93.9%（κ = 0.914）** —— 这是**标签稳定性**的证据，**不是人工一致率**。
  因此归因分布属「单标注者 + 自一致率佐证」的强度，**不作为强结论引用**。
  方法文档 [`badcase_method.md`](badcase_method.md) 定义的完整流程（人工标注 ≥40 条后算人机 κ）
  **未执行**。
  > **⚠️ 一条待查线索 —— 请连同抽样背景一起读**：人工标注的 20 条子集中有 **9 条判为
  > `gold_error`（标准答案有误）**。但这 20 条**取自「多模型共错」的 104 条高危候选池**，
  > 而标准答案有误的题本就会向该池富集 —— 因此 45% 是这个**池子**的比例，
  > **不能外推到全库**（全库独立审计为 **56/61 无缺陷**）；样本量也远低于方法文档要求的 40 条。
  > 方法文档明确「`gold_error` ≥3% ⇒ 需修正已发布准确率」，故如实记录为后续核查项。
- **标准答案审计**：独立进行（不看模型作答），61 题中 **56 题（91.8%）无缺陷**，
  标出 5 题（3× D3 事实错误、2× D2 多解）。程序机械扫描与 LLM 审计**互补**
  —— 程序抓到 `prox-zh-156`（两个选项文字完全相同）而 judge 漏了，
  judge 抓到 `prox-zh-183` 而程序漏了。**任何单一方法都找不全。**

## 8. 工程层面的诚实声明

- **`temperature` 在本池子上被忽略**（实测：三个臂同题 ×6 @ `temperature=1.0`
  均只产生 1 种输出）。因此「固定温度 = 可复现」**不成立**：
  同题重复 10 次，答案全同率最低的模型只有 **28.0%**。
  重复采样是唯一能量化确定性的手段，且它衡量的是**模型属性，不是抽样误差**。
  （`deepseek-v4-pro` 与 `qwen3.8-flash` 未做该探测，五臂的 `temperature=0.1` 是冻结值而非实测结论。）
- **`resp_model` 字段只是回显请求名**，不含后端信息，**不能用于别名检测**；
  本项目改用行为指纹（30 题 × 各臂答案一致率，阈值 80%）。
  ⚠️ 该检测**必须先剔除空响应** —— 曾出现"三臂 93–100% 一致"的假象，
  全部由共同返回空 `content` 造成。
- **`manifest.params_effective` 有 13 处与实际请求参数不符**（3 处在权威批次上）。
  报告结论不受影响 —— **raw 记录里的 `params` 才是真值**，问题字段不能单独作证据。
  见 [`../reports/RUN_INVENTORY.md`](../reports/RUN_INVENTORY.md) §4.6。
- **免费 / 预览档可能限流或变更**：`longcat-2.5-preview-free` 与 `mimo-v2.6-flash`
  均为免费档，跑批中途的限流或后端变更会影响数据可比性。
- **安全维度仅覆盖 4 个模型**（`deepseek-v4-pro` 是判卷方，未参评），
  且判卷方与 `deepseek-v4.1-flash` 同厂 —— 潜在对齐偏好不可完全排除。
