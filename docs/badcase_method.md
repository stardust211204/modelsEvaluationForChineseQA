> **一处设计演化**：本文 §1 的 8 类是**单一标注流程**的标签集。实际执行时发现，把
> `gold_error` 放进主流程会让 judge 把 **53/99 = 53.5%** 的错题判成「标准答案是错的」
> —— 那等于说题库过半的"错题"模型其实都答对了，不可能成立。故拆成**两阶段**：
> 阶段① 归因只用 **7 类**（不含 `gold_error`，并明确告诉 judge「标准答案是否有缺陷
> 不在你的判断范围内」），阶段② 独立做标准答案审计（D1 选项重复 / D2 多解 / D3 事实错误）。
>
> **本文 §4「不要做的事」纪律仍然成立且未被违反**：归因分布之所以不能作为强结论引用，
> 正是因为**只有 LLM 自一致率、没有人工一致率**。完整对照见
> [`limitations.md`](limitations.md) §7。

## 0. 为什么现在这份清单还不能用

我们已经产出的 `runs/c2-full/badcase_review.jsonl`（100 条）**只是候选池**：

* 它的分层依据是**启发式归因**，而该启发式实测只是「文本长度带」
  （三档 content 中位 239 / 622 / 865）。**拿它当标签等于自我循环。**
* 它没有一致率证据。单个标注者的标签，和启发式一样需要被验证。

所以执行方法要解决两件事：**标签怎么定**，以及**标签凭什么可信**。

---

## 1. 标签集（闭合、可判定、8 类）

ErrorMap 的关键贡献是把「答错」拆成互斥的原因。移植到我们的 MCQ 场景：

| 标签 | 含义 | 判据（可操作） |
| --- | --- | --- |
| `knowledge_gap` | 知识缺失 | 推理里**没出现**任何与正确项相关的概念 |
| `reasoning_error` | 推理链错误 | 提到了正确概念，但推导过程有明确错误 |
| `option_confusion` | 选项混淆 | 理解正确，选中的是与正确项**相似或相邻**的干扰项 |
| `question_misread` | 误读题干 | 在回答**另一个问题**（ErrorMap 列为被忽视的类型） |
| `detail_omission` | 遗漏关键细节 | 漏掉题干里的限定条件（"除了""最不""在 X 条件下"） |
| **`gold_error`** | **金标准有误** | 模型的答案**其实是对的**，是标准答案错了 |
| `format_parse` | 格式/解析 | 答案实质正确，但被我们的口径判成错 |
| `cannot_tell` | 无法判断 | 信息不足 |

**两个必须保留的类别**：

1. **`gold_error`** —— ErrorMap 把 **dataset noise** 与模型能力**并列**为失败原因。
   我们项目的准确率**从头到尾假设金标准是对的，从未验证过**。
   文献里金标准错误率并不低（检索到的 BioNLP 工作报告 dev set **5.3%（95% CI 2.7–9.2%）**）。
   ★ 这是本次归因**最可能产出的新结论**，而且它直接影响已发布的所有准确率数字。
2. **`format_parse`** —— 本项目自己的主题就是"静默失效"。
   C5 首轮那次事故（示范格式导致 393/450 判不出）本质就是这一类。
   把它单列，才不会把"我们的口径问题"记到模型头上。

> 与现有 `Attribution` 枚举的关系：现有三档（factual / reasoning / option_confusion）
> 是**启发式**；上面八档是**人工标签集**。两者不合并，人工标签为准。

## 2. 执行步骤

### 步骤 1 · 扩充候选池（10 分钟，脚本）

当前 100 条按 `arm × 启发式` 分层，**过度偏向"话多"的题**。改为：

* 按 **`arm × 学科`** 分层配额（学科是独立于归因的维度，不会循环）
* **强制纳入全部 `mentions_gold_text = True` 的条目**（"擦肩而过"，最有信息量）
* 强制纳入全部 `option_confusion` 候选（验证"相邻选项"是否真是混淆）
* 目标 **120 条**（HANDOFF 原定 80–120）

### 步骤 2 · 双标注（这是可信度的全部来源）

**单标注者的标签不能用**。两种做法，建议都做：

| 做法 | 成本 | 给出什么 |
| --- | --- | --- |
| **A. 你自己标两遍**（间隔 ≥1 天，30 条子集） | ~40 分钟 | **重测一致性**（你自己稳不稳） |
| **B. LLM 作第二标注者**（全 120 条） | ~15 分钟 + 少量 API | **人机一致率** |

做法 B 用哪个模型都行，但**必须与被评模型不同家族**（否则又是一次 self-preference）。
可复用 C4 的 judge 端点。

### 步骤 3 · 报告一致率，再报告分布

* 用 **Cohen's κ**（两标注者）或 **Krippendorff's α**（可处理缺失值、多标注者）。
  检索到的方法学条目明确区分 observed disagreement `D_o` 与 expected disagreement `D_e`
  —— 这正是 α 的定义，也解释了为什么**不能用"一致率"代替 κ**：
  若某一类占 80%，两个瞎标的人也能有 80% 一致率。
* **判定门槛（建议，需你确认）**：
  * κ ≥ 0.6 → 标签可用，分布可写进报告
  * 0.4 ≤ κ < 0.6 → 只报告"哪些类难标"，**不报告分布**
  * κ < 0.4 → 标签集本身要重做

### 步骤 4 · 递归分层，形成「失败签名」

ErrorMap 第二阶段是**递归分组**构造分层分类法。对我们的规模（120 条）不必做完整递归，
但要产出一张**每个模型一张的失败签名表**：

```
模型 X：knowledge_gap 12 | reasoning_error 9 | option_confusion 5 | question_misread 2 | gold_error 3 | …
```

★ 价值不在总数，在**形状差异**：若某模型 `option_confusion` 显著偏高，
说明它的问题在"选项辨析"而非"知识"——这直接指导该补什么数据。

### 步骤 5 · 金标准审计（独立产出）

把 `gold_error` 的条目单独列出，逐条给出"为什么模型的答案是对的"。
这是**可交付的独立成果**：它是对现有题集的一次质量审计。

> ⚠️ 若确认存在金标准错误，**已发布的所有准确率数字都需要重新计算**，
> 并在报告里说明修正幅度。这是必须走的流程，不能只在附录提一句。

## 3. 与本项目其他结论的接口

| 归因结果 | 会验证/推翻什么 |
| --- | --- |
| `option_confusion` 占比高 | 解释 C6 的乱序敏感性（选项顺序一变答案就变） |
| `format_parse` 占比高 | 呼应 C2「严格口径 0 条可判」与 C5 首轮事故 |
| `gold_error` 占比 ≥3% | **推翻/修正所有已发布准确率** |
| `question_misread` 占比高 | 提示题干表述问题，属于题集质量问题而非模型问题 |

---

## 4. 不要做的事

* ❌ **不要**把启发式归因分布写进报告（它只区分话多话少）。
* ❌ **不要**用"一致率"代替 κ。
* ❌ **不要**只报分布不报一致率 —— 那和启发式没有区别。
* ❌ **不要**在 κ < 0.6 时仍然给出精确百分比。
* ❌ **不要**把 `gold_error` 混进"模型答错"，也不要把 `format_parse` 记到模型头上。
